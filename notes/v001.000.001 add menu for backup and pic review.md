## Will it run on a MacBook Air?

**Not as-is.** The backup logic is portable, but several parts are Raspberry Pi / Linux–specific. You’d need a few changes for it to run correctly on macOS.

---

### 1. **LED blinking (Pi-only)**

- **`blink_led.py`** runs **`blink.sh`**, which uses `/sys/class/leds/ACT` and `/sys/class/leds/PWR` (Pi 5 power/activity LEDs).
- Those paths don’t exist on a Mac, so the script will fail when it tries to blink the LED (e.g. when `ToggleLed` is used in `auto_backup.py`).

**Fix:** Make LED support optional: detect the platform (or absence of those sysfs paths) and skip starting `blink.sh` on non-Pi (e.g. on Mac), or use a no-op implementation there.

---

### 2. **Unmount / dismount**

- **`file_watcher.py`** uses **`gio mount -u <volume>`** to unmount. That’s a Linux/GNOME tool and isn’t on macOS.
- On Mac you’d use something like **`diskutil unmount`** or **`umount`** instead.

**Fix:** In `dismount()`, branch on the OS (e.g. `platform.system() == 'Darwin'`) and call the appropriate Mac unmount command instead of `gio`.

---

### 3. **Terminal for tailing the log**

- **`main.py`** and **`terminal_tailer.py`** use **`lxterminal`** with `-e 'tail -f ...'`. That’s a Raspberry Pi OS / Linux terminal; macOS doesn’t have it.
- The `-e` and “run this command” behavior also differ on macOS Terminal.

**Fix:** On macOS, use a different way to show the log: e.g. run `tail -f` in the current terminal, or use `open -a Terminal` / AppleScript to open Terminal with a command that runs `tail -f <log_file>`.

---

### 4. **Paths in `config.json`**

- Paths are set up for Linux:
  - **Home:** `/home/dgarrett/...` → on Mac typically `/Users/<username>/...`
  - **External drives:** `/media/dgarrett/...` → on Mac external volumes are under **`/Volumes/<VolumeName>/`**
  - **Phones/cameras (MTP/PTP):** `/run/user/1000/gvfs/...` → on Mac there is no GVFS; devices often show up under **`/Volumes/`** with different names, or via Photos/Image Capture.

So the same `config.json` won’t work on the Mac without updating every path to match macOS (and possibly rethinking how you add phone/camera sources, since they’re not under GVFS).

---

### 5. **What already works on Mac**

- **`dir_sync.sh`** and **`dir_sync.py`** use standard **bash** and **rsync**; macOS has both (rsync options you use are standard).
- **`FileWatcher`** logic (checking if paths exist) is fine; only the unmount implementation needs to be OS-specific.
- **`JsonConfigReader`**, **`DirSync`**, and the overall flow in **`main.py`** / **`auto_backup.py`** are portable.

---

## Summary

| Component        | On MacBook Air                          |
|-----------------|------------------------------------------|
| Rsync backup    | Works (paths must match Mac filesystem) |
| Config paths    | Must be updated for macOS               |
| LED blinking    | Will fail unless made optional/stubbed  |
| Unmount         | Will fail unless you use `diskutil`/`umount` |
| Log tail window | Will fail unless you switch off lxterminal |

So: it will **not** run correctly on a MacBook Air without the changes above. With optional LED, Mac-specific unmount, a different way to show the log, and a Mac-specific `config.json`, the same project can run correctly on a MacBook Air.

### 1. **`menu.py`** – Menu GUI

- **On startup:** Starts `main.py` (backup) automatically. The first option shows **“Stop Backup”**.
- **Option 1 – Backup:** Toggles the backup process.  
  - Backup running → **“Stop Backup”** (click to stop).  
  - Backup stopped → **“Start Backup”** (click to start).
- **Option 2 – Pic Quality Review:** Toggles the review process.  
  - Not running → **“Start Pic Quality Review”**.  
  - Running → **“Stop Pic Quality Review”**.
- **Option 3 – Exit:** Stops both the backup and pic quality review processes, then closes the app.

Details:

- Backup and pic review are run as **subprocesses** with `start_new_session=True`. Stopping them uses the **process group** so child processes (e.g. `lxterminal` from `main.py`) are also terminated.
- A **poll** runs about once per second so if a process exits on its own (e.g. crash), the button labels (Start/Stop) stay correct.
- Uses **sv_ttk** if installed (`pip install sv-ttk`); falls back to normal tkinter if not.
- **Status line** at the bottom shows the current action (e.g. “Backup running.”, “Pic Quality Review stopped.”).

---

### 2. **`pic_quality_review.py`** – Placeholder for Pic Quality Review

- Intended to be **replaced later** with your real “rate quality of backed-up photos” logic; the menu already starts and stops this script.

### How to run on the Pi 5

From the project directory:

```bash
python menu.py
```

Backup starts automatically; use the menu to stop/start backup, start/stop pic quality review, or exit and stop everything.
