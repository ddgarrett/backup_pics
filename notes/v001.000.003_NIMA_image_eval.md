Summary of what’s in place:

## 1. **`image_evaluator.py`** (main script)

- **Input**: Single directory path; recursively finds all JPEGs (`.jpg`/`.jpeg`) in that directory and subdirectories.
- **Output**: Writes `image_evaluation_results.json` in that directory (or `--output`) with:
  - **Relative path** to each image
  - **File info**: `file_size_bytes`, `file_size_mb`, `width`, `height`
  - **CLIP-IQA**: `clip_iqa_score` in [0, 1] (and `clip_iqa_error` if it fails)
  - **MUSIQ**: `musiq_score` in [1, 10] (and `musiq_error` if it fails)
  - **evaluated_at**: UTC timestamp
- **Incremental**: Loads existing JSON, only runs CLIP-IQA and MUSIQ on images whose `relative_path` is not already in the file, then merges and overwrites the JSON.
- **CLIP-IQA**: Implemented with **PIQ** (PyTorch); no TensorFlow. Uses the default “Good photo” vs “Bad photo” prompt.
- **MUSIQ**: Uses **TensorFlow Hub** by default (`https://tfhub.dev/google/musiq/ava/1`). Optional **TFLite** via `--musiq-tflite path/to/musiq.tflite`.
- **Device**: `--device cuda` / `mps` / `cpu` for the PyTorch (CLIP-IQA) part.

## 2. **`IMAGE_EVALUATOR_README.md`**

- **Installation**: Pillow, numpy, torch, piq, tensorflow, tensorflow_hub (and optional `tflite-runtime`).
- **TFLite for MUSIQ**:
  - Install TensorFlow (and TensorFlow Hub).
  - Download the Hub model and save as SavedModel (helper script below).
  - Convert SavedModel → TFLite with `TFLiteConverter.from_saved_model()`, using `SELECT_TF_OPS` if needed.
  - Run the evaluator with `--musiq-tflite path/to/musiq.tflite`.
- **Training data**: Notes that CLIP-IQA uses PIQ’s pre-trained CLIP and tokens; MUSIQ uses the pre-trained AVA model; custom MUSIQ models can be exported to SavedModel and then converted to TFLite the same way.

## 3. **Helper scripts**

- **`save_musiq_saved_model.py`**: Downloads the MUSIQ Hub model and saves it as a SavedModel (for TFLite conversion).
- **`convert_musiq_to_tflite.py`**: Converts that SavedModel to a `.tflite` file (with `TFLITE_BUILTINS` + `SELECT_TF_OPS`).

## 4. **`requirements_image_evaluator.txt`**

- Lists: Pillow, numpy, torch, piq, tensorflow, tensorflow_hub (and optional `tflite-runtime`).

### Usage examples

```bash
# All JPEGs under a directory, default output path
python image_evaluator.py /path/to/images

# Custom output path
python image_evaluator.py /path/to/images --output /path/to/results.json

# Use a TFLite MUSIQ model
python image_evaluator.py /path/to/images --musiq-tflite ./musiq.tflite

# Use GPU for CLIP-IQA
python image_evaluator.py /path/to/images --device cuda
```

**Note**: CLIP-IQA is PyTorch-only (PIQ); there is no TFLite version. TensorFlow Lite is used only for MUSIQ when you convert the Hub model and pass `--musiq-tflite`. The README describes how to install TFLite and convert the MUSIQ SavedModel to TFLite.

Summary of changes:

1. **Write after each image**  
   After every evaluated image, the script updates the results dict and writes the full JSON file. So each new image adds one row’s worth of data and it’s saved immediately.

2. **Atomic writes**  
   The JSON is written to a temporary file (`.json.tmp`), flushed and fsync’d, then the temp file is renamed over the real path. If the process is killed during the write, the original file is unchanged.

3. **Progress message**  
   After each save it prints something like `-> saved (N results)` so you can see progress.

If you stop the program (Ctrl+C, kill, or crash), the JSON file already contains every image that was fully evaluated before the stop. On the next run, those images are loaded from the file and skipped; only remaining images are processed.

Summary of changes for speed without TFLite:

### 1. **Resize before inference (largest gain)**  
Your images are 4080×3071 (~12.5M pixels). Both models are now run on a **resized** version so the longest side is at most **512 px** by default.

- **CLIP-IQA**: Gets a 512-max-side image instead of full resolution (CLIP is trained at 224/384 anyway).
- **MUSIQ**: Gets JPEG bytes from the same resized image instead of the full 2–4 MB file.

This greatly reduces compute and memory. You can change the size with `--max-size` (e.g. `--max-size 384` for faster, `--max-size 768` for a bit more accuracy).

### 2. **Reuse the CLIP-IQA model**  
The CLIP model was being created for every image. It’s now created **once** before the loop and reused for all images, so you pay the load cost only once.

### 3. **`torch.inference_mode()`**  
Replaced `torch.no_grad()` with `torch.inference_mode()` for a bit of extra PyTorch speed.

### 4. **New option: `--max-size`**  
- **Default: 512** – resize so the longest side is 512 px before running either model.  
- **`--max-size 384`** – faster, slightly less accurate.  
- **`--max-size 768`** – slower, slightly more accurate.  
- **`--max-size 0`** – no resize (original behavior, full resolution; slow).

**Example (default 512):**
```bash
python image_evaluator.py /path/to/images
```

**Faster (384):**
```bash
python image_evaluator.py /path/to/images --max-size 384
```

**Full resolution (no resize):**
```bash
python image_evaluator.py /path/to/images --max-size 0
```

The JSON still stores the **original** width/height from the file; only the evaluation runs on the resized image. On a Pi 5, going from full 4080×3071 to 512 on the long side should cut per-image time from several minutes to well under a minute in typical runs.
