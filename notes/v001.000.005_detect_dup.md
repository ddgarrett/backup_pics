## New script: `scene_duplicates_by_score.py`

It does the following:

1. **Loads scores** for one day directory from:
   - `collect_score.csv` (if present), using `musiq_score` or `calculated_score`, or  
   - `image_evaluation_results.json` (MUSIQ/AVA `musiq_score`).

2. **Sorts images by score** (highest first) and treats order as “best first.”

3. **Finds scene duplicates** using **imagededup’s CNN** (not hashing), so “same scene, different angle/zoom/composition” is detected. For each image in score order it only marks **lower-scoring** images as duplicates of that keeper, so the best shot per scene is always kept.

4. **Operates per day**: you pass a single directory (e.g. `2024-09-10`); only images under that directory are compared.

### Usage

```bash
# Install once (imagededup uses PyTorch under the hood)
pip install -r requirements_scene_duplicates.txt

# Run on a day folder (must already have scores from image_evaluator.py)
python3 scene_duplicates_by_score.py /path/to/2024-09-10

# Softer “same scene” (more pairs marked duplicate)
python3 scene_duplicates_by_score.py /path/to/day --threshold 0.5

# Use combined score from compare_image_quality_models.py
python3 scene_duplicates_by_score.py /path/to/day --score-attr calculated_score

# Save report and get only duplicate paths (e.g. for a delete/move script)
python3 scene_duplicates_by_score.py /path/to/day -o report.json --list-remove
```

### Options

| Option | Purpose |
|--------|--------|
| `--threshold` | Min cosine similarity to treat as same scene (default **0.6**). Lower → more duplicates. ~0.5 = “same place, different framing”; ~0.8 = stricter. |
| `--score-attr` | `musiq_score` (default) or `calculated_score`. |
| `--output` / `-o` | Write JSON with `keeper_to_duplicates` and `duplicate_to_keeper`. |
| `--list-remove` | Print one duplicate path per line (for piping into your own script). |

## EXIF GPS filtering in `scene_duplicates_by_score.py`

**Behavior**

- **Both photos have GPS:** The duplicate (CNN similarity) check runs only if the candidate is within **0.5 miles** of the keeper. If it’s farther, the pair is skipped (no encoding comparison).
- **One or both lack GPS:** The script behaves as before and always runs the duplicate test (no distance filter).

**Implementation details**

- **`get_gps_from_exif(image_path)`** – Reads EXIF GPS and returns `(lat, lon)` in decimal degrees, or `None` if missing/invalid. Uses Pillow’s `getexif()` and the GPS IFD; DMS → decimal and refs (N/S, E/W) handled, including byte refs.
- **`haversine_miles(lat1, lon1, lat2, lon2)`** – Distance in miles between two WGS84 points.
- **`build_gps_cache(image_root, relative_paths)`** – Builds `relative_path → (lat, lon) | None` for the day’s images once.
- In **`find_duplicates_by_score`**, when considering a keeper vs a lower-scoring candidate, if both have GPS and `gps_radius_miles` is set, the script skips the CNN check when `haversine_miles(...) > gps_radius_miles`.

**CLI**

- **`--gps-radius-miles M`** (default **0.5**) – When both have GPS, only test for duplicate if the candidate is within **M** miles of the keeper.
- **`--gps-radius-miles 0`** – Disables GPS filtering; every pair is tested as before.

**Report**

- Console and JSON report now include the GPS radius (or “disabled” when 0).

No new dependencies: EXIF is read with Pillow (already used by `image_evaluator`). Example:

```bash
# Default: 0.5 mile radius when both have GPS
python3 scene_duplicates_by_score.py /path/to/day

# Stricter: only test duplicates within 0.25 miles
python3 scene_duplicates_by_score.py /path/to/day --gps-radius-miles 0.25

# Ignore GPS (test all pairs)
python3 scene_duplicates_by_score.py /path/to/day --gps-radius-miles 0
```

does that similarity threshold seem reasonable>?

---

**Cursor**


**0.65 is a reasonable default** for “same scene, different view” (different angle/zoom/composition).

- **imagededup’s default** for CNN is **0.9**, which is for near-duplicates (almost the same crop). You’d miss a lot of “same place, different framing” pairs at that level.
- **0.5** “allows large deviation” and is often used for different viewpoints; it can pull in more false positives (different scenes that look similar).
- **0.65** sits between them: loose enough to catch same-scene shots with different framing, but a bit stricter than 0.5 to reduce false pairs.

**Practical tuning:**

- If you see **obvious same-scene pairs not being grouped** (e.g. wide vs zoomed of the same spot), try **0.55–0.6**.
- If you see **different scenes grouped together**, try **0.7–0.75**.

You can override anytime with `--threshold`, e.g.:

```bash
python3 scene_duplicates_by_score.py /path/to/day --threshold 0.6
```

## 1. **Poor quality threshold (score &lt; 4)**
- **`POOR_QUALITY_THRESHOLD = 4.0`**  
  Images with `musiq_score < 4` are **not** used in duplicate detection (neither as keeper nor as candidate).

- **`get_datetime_taken(image_path)`**  
  Uses EXIF **DateTimeOriginal** (or **DateTime**), then falls back to the file’s modification time.  
  Value is written as an ISO-style string in the **`date_time_taken`** column.

## 3. **Status CSV in the image folder**
- **Output file:** `image_scores_and_status.csv` in the same directory as the images (the day directory).

  - **status** – see below
  - **dup_photo** – relative path of the keeper when this photo is a duplicate (empty otherwise)

## 4. **Status rules**
- **Score &lt; 4:** `"poor quality"` (and not used in duplicate detection).
- **Duplicate of a higher-scoring photo:** `"dup"`, and **dup_photo** = that keeper’s `relative_path`.

- **Score &gt; 5:** `"good"`.

Summary of changes:

- **Removed** the haversine implementation and the Earth-radius constant.
- **Replaced** with **`distance_meters_flat()`**, which:
  - Treats lat/lon as a local flat grid.
  - Converts latitude difference to meters with ~111,320 m/degree.
  - Converts longitude difference to meters with the same scale × cos(mid-latitude).
  - Returns the Euclidean distance: √(Δlat² + Δlon²) in meters.

For distances on the order of 200 m, this approximation is easily accurate enough and avoids any curvature-of-Earth logic.
